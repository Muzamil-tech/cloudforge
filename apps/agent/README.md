# CloudForge Agent

The CloudForge agent runs on customer-owned Linux VPS nodes. It enrolls with a
CloudForge control plane, proves its identity on every request, reports host and
Docker facts, and executes a small allowlist of infrastructure operations.

Phase 1 is deliberately narrow:

- Outbound HTTPS only. The agent never listens on a network port.
- RSA-2048 key and a client certificate issued by the control plane certificate
  authority.
- Read-only Docker inspection plus typed lifecycle operations for allowlisted
  PostgreSQL and Redis containers.
- No arbitrary shell execution. The Go implementation links no shell and the
  command executor switches on a fixed enumeration.
- The enrollment token is single-use and is never persisted to `agent.env`.

## Requirements

- Linux on `amd64` or `arm64`
- systemd (for the packaged service)
- Docker, if Docker inventory is wanted. The daemon socket must be a Unix socket.
- Go 1.24 or newer to build from source

## Build and test

```sh
go test ./...
go vet ./...
go build ./cmd/cloudforge-agent
```

Release archives are built with:

```sh
make package VERSION=1.0.0
```

This writes `dist/cloudforge-agent_linux_amd64.tar.gz`,
`dist/cloudforge-agent_linux_arm64.tar.gz` and `dist/SHA256SUMS`. The archives
contain the static binary, the systemd unit and this README. The control plane's
`install.sh` downloads the archive named for the host architecture and verifies
it against `SHA256SUMS`.

## Install

On the target host, run the command generated by the server's enrollment panel:

```sh
curl -fsSL https://cloudforge.example.com/install.sh | sudo \
  env CLOUDFORGE_ENROLLMENT_TOKEN=... \
      CLOUDFORGE_CONTROL_PLANE_URL=https://cloudforge.example.com \
      CLOUDFORGE_SERVER_ID=... sh
```

The installer:

1. Downloads the release archive for the host architecture.
2. Verifies its SHA-256 checksum.
3. Creates the `cloudforge-agent` system user and `/var/lib/cloudforge-agent`.
4. Writes `/etc/cloudforge/agent.env` with mode `0600` (without the token).
5. Adds the user to the `docker` group when that group exists.
6. Redeems the enrollment token and writes the agent identity.
7. Enables and starts `cloudforge-agent.service`.

Re-running the installer with an existing identity refreshes the binary and unit
without re-enrolling. Set `CLOUDFORGE_FORCE_ENROLL=1` only after the existing
certificate has been revoked in the control plane.

See `docs/agent/installation.md` for the full installation and upgrade guide.

The self-hosted control-plane host is installed through the same script with
`CLOUDFORGE_BOOTSTRAP=1`. The wrapper reads a short-lived `0600` credential
written by `php artisan cloudforge:bootstrap`, enrolls the agent, and deletes
the credential. The token never appears in `agent.env`, the command line or the
systemd unit. See [self-hosted bootstrap](../../docs/agent/installation.md#self-hosted-bootstrap).

## Commands

```text
cloudforge-agent enroll [flags]   redeem a single-use enrollment token
cloudforge-agent run [flags]      run the agent
cloudforge-agent version          print the agent version
```

`enroll` requires `CLOUDFORGE_CONTROL_PLANE_URL`, `CLOUDFORGE_SERVER_ID` and a
token supplied either through `CLOUDFORGE_ENROLLMENT_TOKEN` or `--token`.

`run` loads the identity from the data directory and starts five loops:
heartbeat, inventory, metrics, command polling and certificate rotation.

### Flags

| Flag | Meaning |
| --- | --- |
| `--control-plane` | Control plane base URL (HTTPS, or HTTP on loopback) |
| `--server-id` | CloudForge server UUID |
| `--data-dir` | State directory, default `/var/lib/cloudforge-agent` |
| `--docker-socket` | Docker Unix socket, default `/var/run/docker.sock` |
| `--ca-file` | Extra PEM CA bundle for the control plane TLS certificate |
| `--log-level` | `debug`, `info`, `warn` or `error` |
| `--token` | Enrollment token (prefer the environment variable) |
| `--force` | Replace an existing local identity |
| `--timeout` | Enrollment request timeout |
| `--heartbeat-interval` | Heartbeat cadence |
| `--command-poll-interval` | Pause after an empty command poll |
| `--command-poll-wait` | Long-poll wait in seconds, `0`–`25` |
| `--metrics-interval` | Metrics sample cadence |
| `--inventory-interval` | Inventory refresh cadence |
| `--request-timeout` | HTTP request timeout |
| `--rotate-before` | Rotate the certificate this long before expiry |

### Environment

| Variable | Default |
| --- | --- |
| `CLOUDFORGE_CONTROL_PLANE_URL` | required |
| `CLOUDFORGE_SERVER_ID` | required |
| `CLOUDFORGE_ENROLLMENT_TOKEN` | only for enrollment |
| `CLOUDFORGE_MACHINE_ID` | empty; reads `/etc/machine-id` |
| `CLOUDFORGE_DATA_DIR` | `/var/lib/cloudforge-agent` |
| `CLOUDFORGE_DOCKER_SOCKET` | `/var/run/docker.sock` |
| `CLOUDFORGE_CA_FILE` | empty, uses the system trust store |
| `CLOUDFORGE_POSTGRES_IMAGE` | `postgres:16-alpine` |
| `CLOUDFORGE_REDIS_IMAGE` | `redis:7-alpine` |
| `CLOUDFORGE_LOG_LEVEL` | `info` |
| `CLOUDFORGE_HEARTBEAT_INTERVAL` | `30s` |
| `CLOUDFORGE_COMMAND_POLL_INTERVAL` | `5s` |
| `CLOUDFORGE_COMMAND_POLL_WAIT` | `25` |
| `CLOUDFORGE_METRICS_INTERVAL` | `30s` |
| `CLOUDFORGE_INVENTORY_INTERVAL` | `10m` |
| `CLOUDFORGE_REQUEST_TIMEOUT` | `45s` |
| `CLOUDFORGE_CERTIFICATE_ROTATE_BEFORE` | `720h` (30 days) |

Duration values accept Go syntax (`30s`, `10m`) or plain seconds. Invalid
values fall back to the default.

## Files on disk

| Path | Mode | Purpose |
| --- | --- | --- |
| `/var/lib/cloudforge-agent/agent.key` | `0600` | RSA private key |
| `/var/lib/cloudforge-agent/agent.crt` | `0644` | Issued client certificate |
| `/var/lib/cloudforge-agent/ca.crt` | `0644` | Control plane CA certificate |
| `/var/lib/cloudforge-agent/commands.json` | `0600` | Terminal command results for deduplication |
| `/etc/cloudforge/agent.env` | `0600` | Service configuration, no token |

The identity is written atomically. If the process dies between writing the key
and certificate, enrollment can be retried; `run` refuses to start without a
complete identity.

## Request authentication

Every authenticated request carries:

```text
X-CloudForge-Fingerprint  lowercase SHA-256 fingerprint of the client certificate
X-CloudForge-Timestamp    Unix seconds
X-CloudForge-Nonce        base64url nonce, 16–128 characters
X-CloudForge-Signature    base64 RSA-SHA256 signature
```

The signature covers:

```text
METHOD
request-uri
timestamp
nonce
sha256(raw-body)
```

`request-uri` is the path plus optional query string, not the full URL. The
control plane caches nonces for twice the allowed clock skew and rejects
timestamps outside the skew window.

The TLS layer also presents the client certificate. When a trusted TLS
terminator handles mutual TLS, configure it to forward the certificate serial
and enable `CLOUDFORGE_REQUIRE_CLIENT_CERT_HEADER` on the control plane.

## Docker access

The agent only accepts an absolute Unix socket path. Endpoints containing `://`
(such as `tcp://`, `ssh://` or `npipe://`) are rejected at configuration load.
It calls `GET /version` and `GET /info` for capability reporting, and performs a
small, typed set of resource operations:

- pull `postgres:16-alpine` or `redis:7-alpine`;
- create a container with a control-plane-generated name and persistent volume;
- bind one port to `127.0.0.1` only;
- start, stop, inspect and remove that container and its volume.

The agent builds the Docker request itself. It never accepts an image name,
command, mount, port mapping or arbitrary Docker API path from the control
plane. There is no container enumeration and no generic Docker proxy.

Managed containers carry `cloudforge.managed`, `cloudforge.resource_id` and
`cloudforge.resource_type` labels. The generated database password is returned
to the control plane once; the control plane encrypts it and removes it from the
generic command result.

If the image already exists locally, the agent skips the registry request. For
the default images it tries `mirror.gcr.io/library/...` first, then Docker Hub,
then `public.ecr.aws/docker/library/...`. Each registry attempt is bounded so a
blocked CDN cannot hold the command queue for the whole create TTL. An operator
can pin an internal registry with `CLOUDFORGE_POSTGRES_IMAGE` and
`CLOUDFORGE_REDIS_IMAGE` in `/etc/cloudforge/agent.env`.

## Certificate rotation

The agent checks its certificate every 12 hours. Inside the rotation window
(30 days by default) it generates a new RSA key and CSR, calls
`POST /api/agent/v1/certificates/rotate`, verifies the returned certificate
against the returned CA and the expected server ID, writes the new identity
atomically and swaps the in-memory identity. The control plane revokes the
previous active certificate with reason `rotated` in the same transaction, so
only the new certificate remains active.

If the certificate has already expired, the agent logs an error and requires
re-enrollment; it keeps running and retrying rather than exiting.

## Development

Run a local control plane on `http://127.0.0.1:8000`, create a server and issue
an enrollment token in the dashboard, then:

```sh
go run ./cmd/cloudforge-agent enroll \
  --control-plane http://127.0.0.1:8000 \
  --server-id <uuid> \
  --data-dir "$(mktemp -d)" \
  --token <token>

go run ./cmd/cloudforge-agent run \
  --control-plane http://127.0.0.1:8000 \
  --server-id <uuid> \
  --data-dir <same-directory>
```

Loopback HTTP is the only non-HTTPS endpoint the configuration accepts.
